# Notion-to-website content sync

This worker treats a Notion data source as the canonical source for public website content. It queries all pages with bounded retries and pagination, keeps only pages whose configured status is published, retrieves each page’s block tree, renders a small Markdown/MDX-compatible subset, and writes one generated file per page under `content/`.

The worker is `scripts/notion-content-sync.mjs`. It has no third-party runtime dependency and runs on Node 22. The generated files include the title, slug, content type, audience, description, publication status, Notion page ID, canonical Notion URL, and last-edited timestamp in frontmatter.

## Required configuration

Copy `.env.notion-content.example` to a local ignored environment file or configure the equivalent GitHub Actions secret and variables. `NOTION_TOKEN` and `NOTION_CONTENT_DATA_SOURCE_ID` are required. The Notion integration must have access to the data source and read access to the published pages.

The default title property is `Title`, status property is `Status`, and published value is `Published`. Override those names through environment variables when the content database uses a different schema. Slugs are taken from the configured `Slug` property when present; otherwise they are derived from the title.

## Safety behavior

Use `DRY_RUN=1` for local inspection or manual workflow runs. A live run writes only the `content/` directory and its `.notion-sync-manifest.json` ownership file. Files previously generated by this worker are removed only when their filenames are absent from the latest published-page set. The path guard prevents a slug from escaping `CONTENT_DIR`.

The workflow runs hourly with a non-overlapping concurrency group. Scheduled runs commit generated changes back to the repository, allowing the existing Vercel deployment to publish them. Manual runs default to dry-run; selecting a live manual run commits changes.

## Supported Notion blocks

The renderer supports paragraphs, headings, bulleted and numbered lists, to-dos, quotes, callouts, dividers, code blocks, images, bookmarks, embeds, and child-page headings. Unsupported block types are skipped rather than represented as guessed content. Notion-hosted file URLs may expire; for durable public media, prefer external URLs or a separate asset pipeline.

## Local verification

```bash
DRY_RUN=1 NOTION_TOKEN=... NOTION_CONTENT_DATA_SOURCE_ID=... \
  node scripts/notion-content-sync.mjs
```

The worker prints a JSON summary containing the number of queried pages, published pages, output directory, and content hashes. The project’s existing `scripts/notion-to-sheets.mjs` remains separate: it mirrors Revenue Ops to Google Sheets, while this worker publishes website content as generated MDX.
